# Geographic coverage audit — Dehradun, India

Audit of 2026-11-07 against the working tree (14 reader and synthesis agents, every claim cites a file). Read with [FREE-DATA-PLAN.md](FREE-DATA-PLAN.md).

## 1. Short answer

**The app runs anywhere on Earth, but it does not *cover* everywhere equally.** Its layers fall into four coverage models:

| Model | Meaning | Share of layers |
|---|---|---|
| **global** | One worldwide source, no geographic gate in code (Esri/OSM basemaps, terrain, satellites, launches, USGS quakes, FIRMS, GIBS imagery, wind, OSRM routing, Photon geocoding, Open-Meteo, iNaturalist, Radio Browser, AIS, OpenSky/adsb.lol) | ~55% |
| **regional** | A single national/continental provider with no non-US/Canada equivalent registered (NOAA radar/lightning/cyclones, NIFC fire perimeters, FAA drone airspace, ECCC air quality, DeFlock ALPR, Acartia, S2 GhostMaps) | ~25% |
| **city-list** | Explicit allow-lists of operators (CCTV packs, GTFS-RT transit feeds, GBFS bikeshare, bundled POI cities, the Dehradun region pack) | ~15% |
| **local-receiver** | Only with hardware you run (RTL-SDR ADS-B / FM) | ~5% |

**For Dehradun (30.32 N, 78.03 E):** the globe, terrain, imagery, place search, routing, weather forecast, fires, quakes, satellites, launches, wildlife and the offline region pack all work. Live traffic, street imagery and aircraft work partially. CCTV, transit, bikeshare, ALPR, rain radar, lightning, cyclones, air quality, drone airspace and fire perimeters show nothing — not because of a bug but because no Indian provider is registered. There is no India-specific code path that breaks; "empty" is an honest empty.

**Important caveat about the current working tree:** `vite.config.js` → `server/standalone/vite.config.js:27-29` now passes `freeOnly: true`, and `server/providers/local.js:60-89` plus `server/standalone/free-only.js:6-13` disable Google 3D/Places, Cesium ion, OpenAI/Gemini, TomTom, OpenSky and `/api/flights/track` **regardless of the keys saved in `.env`**. None of this exists at committed `HEAD` (`git show HEAD` has zero `freeOnly` references). So "works with the keys already present" below describes HEAD or a build with Free-only switched off; the dev server as it stands today runs keyless.

## 3. Plain-language verdict for a Dehradun user

### Out of the box (no keys, current Free-only working tree)
You land on a **2D Esri satellite globe draped over keyless Mapterhorn terrain** with the Mussoorie ridge in relief.
